### Post-Incident Review: OAuth Token Replay at HarborPay

HarborPay operates the Meridian API Gateway for payment-service traffic. The gateway uses Envoy Proxy for request routing and sends security telemetry to Splunk Cloud. HarborPay uses Okta Workforce Identity to authenticate administrators. On 7 August 2026, the security team detected repeated requests to the Settlement API carrying the same OAuth 2.0 bearer token from two unrelated network locations. Maya Chen, a senior security engineer at HarborPay, led the incident review.

Investigators determined that the bearer token had been copied from an application log generated by an older debugging configuration. The attacker replayed the token against the Settlement API until the token expired. The incident did not compromise Okta Workforce Identity, and investigators found no evidence that the attacker obtained an administrator password. Splunk Cloud retained the request records used to reconstruct the replay sequence.

HarborPay disabled the debugging configuration, reduced the access-token lifetime, and required mutual TLS between the Meridian API Gateway and the Settlement API. The team evaluated DPoP as an additional proof-of-possession control but did not deploy DPoP during the incident response. HarborPay also updated its Token Handling Standard to prohibit application logs from recording Authorization headers.
