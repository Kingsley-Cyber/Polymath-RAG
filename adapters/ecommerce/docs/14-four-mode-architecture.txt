# 11. Market Frontier formula

Configurable, not law:

[
M(s)=
w_AA+
w_CC+
w_WW+
w_JJ+
w_TT+
w_SS+
w_XX-
w_RR-
w_{sat}Sat
]

Where:

```text
A   = current attention
C   = community richness
W   = whitespace strength
J   = physical-job richness
T   = trend/currentness
S   = physical-commerce reachability
X   = cross-domain/corpus transfer value

R   = redundancy
Sat = saturation/commodity pressure
```

Then diversity-aware selection:

[
M'(s)=M(s)-\lambda\max_{x\in Selected}Sim(s,x)
]

Same controlled exploration logic.

# 45. The overall architecture is now a directional research system

This is what I think is particularly strong about the design.

```text
                 MARKET_DISCOVERY
                       ↓
              Market → Niches

PRODUCT_ANCHORED                 NICHE_LOADOUT
      ↓                              ↓
Product → Market              Niche → Products
      │                              │
      └──────────────┬───────────────┘
                     ▼
             OPPORTUNITY_RESEARCH
               deep qualification
```

All four are different **directions through the same latent commerce space**.

You aren't building four unrelated agents.

You're essentially defining four traversal operators:

```text
MARKET → NICHE
NICHE → PRODUCT SET
PRODUCT → MARKET
OPPORTUNITY → EVIDENCE/QUALIFICATION
```

That is the right abstraction.

## Exact Fable handoff

> **Implement `MARKET_DISCOVERY` and `PRODUCT_ANCHORED_DISCOVERY` as first-class run modes on the existing graph-generic controller. Each receives its own Control Graph, Loop spec, policies/settings, schemas, prompts and report projection while reusing `memory.py`, `context.py`, registry compilation, Hermes native web/browser execution, Polymath MCP, evidence authority, CommentStrengthener, TrendSensor, Product Intake, deterministic scoring/VOI infrastructure, Commercial Intelligence Compiler and Registry Maintenance.**
>
> **`MARKET_DISCOVERY` starts from a broad market seed and maintains isolated blind-field, Trends, corpus and supply discovery lanes until `MERGE_MARKET_SIGNALS`. It then builds a QueryGraph and MarketLattice, applies deterministic surface gain, market-frontier utility and diversity-aware selection, researches retained markets through communities/comments, calculates SignalDivergence, proposes WhitespaceHypotheses, runs bounded VOI correction, and terminates with 3–8 evidence-grounded market/niche scopes plus a Market Discovery report and optional child-run handoffs.**
>
> **`PRODUCT_ANCHORED_DISCOVERY` starts from a physical ProductSeed, resolves ProductIdentity, quarantines user/seller claims, independently performs blind-field, Polymath, current-commerce and optional Trends research, then builds competing ProductMeanings and MarketBridges. Use deterministic reverse-fit utility, diversity-aware market selection and bounded market/sub-niche granularity; deepen communities/comments only for retained bridges, revise rather than overwrite hypotheses, permit explicit MarketReframe and AdjacentMarket/AdjacentProduct discoveries, and terminate with the strongest defensible product→market bridges or `NO_DEFENSIBLE_MARKET`.**
>
> **Both modes persist all canonical state, actions, receipts, context manifests, hypotheses, revisions, evidence gaps, query graphs and handoffs in the existing SQLite Work Graph. CSV/YAML registry assets remain reusable priors only. Runtime discoveries produce RegistryCandidates but never mutate the pinned snapshot. Registry Maintenance remains the only promotion path. All formula results require input/weight/config receipts and bounded robustness checks.**
>
> **Mode handoffs create new child runs with explicit `HandoffPacket`s and provenance rather than changing the parent run's type. Child runs inherit only promoted canonical objects/evidence references and unresolved questions, not the parent's entire context window.**

That gives the two newest modes the same **graph + loop + φ/Python + θ + CSV registry + SQLite memory + context engineering + maintenance + reports** discipline as the rest of Trail-Signal.
