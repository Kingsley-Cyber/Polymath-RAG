Yes. This is the point where I would **formally add Context Engineering as a control-plane concern**. Your SQLite durability solves “what happened?” but it does not by itself solve:

> “What exactly should Hermes/model know right now after 40 graph steps, three research rounds, a crash, context compaction, or a fresh subagent?”

A `working_context.md` is a useful emergency/debugging artifact, but I would **not make Markdown the authority**. You already have the stronger answer available:

> **SQLite owns durable workflow truth. Polymath owns source/evidence truth. The registry owns reusable priors. The Control Graph owns what a step requires. A Context Compiler owns the temporary context window presented to θ.**

That closes the architecture.

## The ownership model

I would lock this:

| Layer                   | Owns                                                                                    | Does NOT own               |
| ----------------------- | --------------------------------------------------------------------------------------- | -------------------------- |
| **Polymath**            | Documents, corpus knowledge, evidence/source content                                    | Current workflow position  |
| **Registry/Git**        | Curated priors, activities, frictions, predicates, query grammar                        | Run state                  |
| **Graph + policies**    | Legal reasoning structure, required context, budgets, authority rules                   | Historical execution state |
| **SQLite**              | Exact run state, Work Graph, actions, receipts, gaps, products, evidence refs, progress | Full source corpus         |
| **Context Compiler**    | What θ sees *for this particular action*                                                | Canonical truth            |
| **Hermes conversation** | Human interaction surface                                                               | Workflow memory            |
| **θ/model context**     | Temporary semantic reasoning                                                            | Durable memory             |
| **Report layer**        | Presentation of canonical state                                                         | New facts/evidence         |

The crucial invariant:

> **A run must remain executable if Hermes's conversation history disappears completely.**

You already wanted that for SQLite. Extend it to context:

```text
delete conversation history
restart Hermes
controller.py step --run nl_123

→ system reconstructs exactly enough context
  to perform the next legal action
```

If it cannot do that, context management is incomplete.

```text
       ↓
```


That gives you **reasoning replay stability**.

# Separate `fact compression` from `semantic compression`

For long runs, you need both.

## Deterministic/state compression

Python can compact:

```text
47 product candidates
→
5 ADVANCE
4 HOLD
38 REJECTED
```

and omit the 38 unless they're relevant.

It can compact evidence:

```text
WORKAROUND_EVIDENCE
coverage = satisfied
independent authors = 9
threads = 4
```

without asking an LLM.

## Semantic compression

θ may create a concise:

```text
"Current community picture"
```

from admitted observations.

But that summary must contain:

```text
derived_from IDs
```

and remain:

```text
DERIVED_SUMMARY
```

not source evidence.

Then the context compiler can choose either:

```text
summary
```

or:

```text
underlying evidence
```

depending on the node.

# What Fable should implement

I would give it this delta:

> **Add explicit Context Engineering to the existing control plane. SQLite remains the sole canonical workflow memory; Polymath remains source/evidence truth; the registry remains reusable-prior truth; Graph/Policy files remain execution-rule truth. Hermes conversation history and model context are never authoritative. Create `context.py` as the sole Context Compiler, but preserve `memory.py` as the only module allowed to access SQLite directly—`context.py` must obtain state through `memory.py` APIs.**
>
> **Every θ-executed Control Graph node must declare a `ContextContract`: required object classes, required EvidenceRoles, branch scope, exclusions, and optional context-budget hints. Before an action is exposed to Hermes, the Context Compiler deterministically assembles a `RunBrief + ActionContext` into a versioned `ContextEnvelope`. It must verify that all required context exists and perform deterministic context backfill from the correct canonical owner: SQLite for workflow state, Polymath for source material, pinned RegistrySnapshot for priors, and Graph/Policy files for rules. Backfill may recover known state but may never conduct new research or create evidence.**
>
> **Freeze the ContextEnvelope with every PENDING action, including its manifest/hash, so crash-resume returns not only the same pending action but the same execution context. No graph step may rely on previous conversational turns being present. A run must remain executable after complete loss of Hermes conversation memory.**
>
> **Use selective reconstruction rather than whole-run prompting. Context priority should preserve constitutional rules and decision-critical objects first, then relevant evidence/contradictions, then supporting priors, while completed/rejected/history data is omitted unless specifically required. Preserve source references and structured receipts rather than repeatedly summarizing summaries. Semantic summaries are derived artifacts with lineage, never evidence.**
>
> **Add phase checkpoints so context recovery may use `latest checkpoint + canonical deltas` instead of replaying the entire run. Subagents receive branch-specific ContextEnvelopes, never the full run; fresh evaluators receive evidence/claims/receipts without the generator's persuasive narrative.**
>
> **Generate an optional `working_context.md` for human inspection and emergency portability, but it is a one-way projection from SQLite and may never be edited back into canonical state. If deleted, it must be reproducible. The ultimate invariant is: deleting chat history, generated Markdown and model memory must not prevent `controller.py step --run <id>` from determining exactly what to do next and reconstructing the context required to do it.**

This is one of the more important additions you've caught.

**SQLite solved durable memory. `ContextContract → Context Compiler → ContextEnvelope` solves durable cognition.**

Without it, long graph/loop runs eventually become dependent on whatever happens to still be in the LLM context window. With it, the context window becomes what it should be: **a temporary, deterministic projection of durable state for one reasoning action**, not the memory system itself.
