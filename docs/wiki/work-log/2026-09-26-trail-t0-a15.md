# TRAIL-INTERFACE T0: unfilled Trail result fields no longer shadow real ones (gap A-15 and its class)

## Contract
- TRAIL-INTERFACE-V1 §4.1 / slice T0 (plan of record 11.504): the gates screen needs a run's real qualifications.

## Changes
- **The root cause is wider than A-15.** TrailSignal's `ResearchResultV1` carries all 12 fields on every operation. The ones an
  operation does not fill arrive as `null` or an EMPTY tuple (`[]` on the wire). The worker skipped only nulls, so every Trail step
  stored `[]` for `qualifications`, `open_gaps`, `redundancy_groups`, `unsupported_hypothesis_ids`, `territories`, `trail_scores`,
  `score_refusals` and (translated) `hypothesis_verdicts`. Readers take the NEWEST occurrence of a key, so the latest step's
  empty list shadowed the real value:
  - the compiled result lost its qualifications (A-15; R7: `[]` while Trail stored 2 qualify results);
  - every `hypotheses.judge` call received `redundancy_groups = []` after the first later Trail step, so Trail could never
    DEDUPLICATE / MERGE redundant hypotheses;
  - `gaps.compile` received `open_gaps = []` whenever an admit step came after the last judge or qualify.
- `trail_client.FIELDS_BY_OPERATION`: the fields each of the 7 bounded operations fills. `trail_client.fills(kind, key)`: false only
  for a Trail result field (or its derived `hypothesis_verdicts`) that the step's operation does not fill.
- `exec_external` (write side) keeps only filled fields. A filled EMPTY list is still kept (a qualify that finds nothing is an answer).
- `service._gather` and the worker's `_newest_output_with` (read side) skip unfilled fields, so runs stored before the fix read
  back correctly in step contexts and in any result compiled from step outputs.
- Stored results are NOT rewritten. `adapter_results` of finished runs (R7) keep what was compiled at the time. The Trail
  interface's view (T1) compiles from step outputs through the fixed readers.

## Proof
- `tests/contracts/test_trail_unfilled_fields.py`, 10 tests:
  - the map equals one re-derived with `ast` from the PINNED Trail source, and `RESULT_FIELDS` equals `ResearchResultV1`'s fields;
  - envelopes are built from the pinned model's own wire defaults;
  - score, qualify and admit steps store only filled fields;
  - an old-style stored run reads back its real qualifications, score refusals, verdicts, open gaps and redundancy groups;
  - a judge step sends the registry's groups;
  - a newer filled empty list still wins.
- Run against the UNFIXED production code, 8 of the 10 fail. The 2 that pass check the premise (the wire default is `[]`) and that a filled empty list wins.
- `tests/contracts` 266 passed; 25 adapter/Trail determinism files: 223 passed, 1 skipped.
  - One test was left out: `test_adapter_service_store.py::test_http_routes_are_thin_wrappers` reads `.env` for the live database, which a worktree does not have. It passes in the main checkout.
- ruff: no new findings in the changed source files.
