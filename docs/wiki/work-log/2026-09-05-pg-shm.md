# WORK LOG — PG-SHM-V1

## Contract

- No Polymath query may fail on `could not resize shared memory segment … No space left on device`. Postgres parallel workers exchange data through POSIX dynamic shared memory under `/dev/shm`; Docker gives a container 64 MB unless `shm_size` says otherwise.
- Now: parallel gather disabled cluster-wide (`ALTER SYSTEM SET max_parallel_workers_per_gather = 0; SELECT pg_reload_conf();` — verified `0` in a fresh session, `pending_restart = false`), so no plan allocates a DSM segment.
- Durable: `shm_size: "1gb"` on the `postgres` service in `compose.yaml`. It takes effect at the next `docker compose up` recreate of that container (deliberately not done mid-ingest: it is a Postgres restart). After that recreate the parallel setting may be restored with `ALTER SYSTEM RESET max_parallel_workers_per_gather`.

## Why (measured 2026-09-05)

- Postgres container log: 192 `No space left on device` errors between 09:48Z and 14:09Z. Failing statements: the routing projection `WITH want AS (SELECT rs.summary_id …)` ×90, the facts/evidence join behind semantic readiness ×56, a facts scan ×33, `SELECT DISTINCT d.corpus_id FROM chunks …` ×10, a projection_receipts join ×2. `/dev/shm` in the container: 64 MB.
- The `project_neo4j` worker logged 11 `DiskFull` "processing failed" events (10:49Z–13:58Z); every affected ticket completed on retry (31 `ok` attempts in 6 h, 0 failed tickets), so the cost was retries and latency, not lost work. The determinism suite's `test_incremental_census` reproduced the same error against the live store.
- After the change: `/documents?corpus_id=cinema` 0.36–0.45 s and `/semantic_readiness` 0.20–0.33 s (three samples each) — no regression from losing parallel plans on this store.

## Changes

- Postgres cluster: `ALTER SYSTEM SET max_parallel_workers_per_gather = 0` + `pg_reload_conf()` (lives in `postgresql.auto.conf`).
- `compose.yaml`: `shm_size: "1gb"` on the `postgres` service with the measurement in a comment.

## Proof

- Fresh-session `SHOW max_parallel_workers_per_gather` = `0`; `pg_settings.pending_restart = false`; `postgresql.auto.conf` carries the line.
- Postgres container log after the change: 0 new `No space left on device` lines in the following minutes (192 in the preceding 24 h; the count is re-checked in the register row).
- Endpoint latencies after: `/documents?corpus_id=cinema` 0.45 / 0.36 / 0.36 s, `/semantic_readiness` 0.23 / 0.33 / 0.20 s.

## Rejected claims

- "Recreate the container now with shm_size." Rejected mid-ingest: a Postgres restart drops every worker connection during the cinema projection pass. The reload-only setting closes the failure class immediately; the compose change makes the fix durable.
- "The failures were the projection worker's fault." Rejected: they are a container resource limit hit by any parallel plan.

## Open contract gaps

- Postgres restarts (e.g. a compose recreate) keep `postgresql.auto.conf`, so parallel stays off until someone resets it after the shm change lands — noted in the continuity report.
