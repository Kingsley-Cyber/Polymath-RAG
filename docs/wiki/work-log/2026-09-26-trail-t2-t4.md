# TRAIL-INTERFACE T2–T4: the Research screens

## Contract
- TRAIL-INTERFACE-V1 §3 / slices T2–T4 (plan of record 11.504). Owner decisions: watch and read; friends see only their runs.

## Changes
- **Navigation.** A Research item for everyone. Friends reach only their own runs, because the route scopes them.
- **The runs list.**
  - Each row: title, outcome in words, adapter, start time, steps.
  - A completed run whose scores were all refused shows amber, not green.
  - Skeleton, error and empty states.
- **A run page.**
  - Header: status, adapter and version, times, agent, a stop banner for a gap, and Cancel (behind a confirm) while live.
  - Outcome: TrailSignal's refusals in words ("A required check wasn't met"), each with the hypothesis it refuses, under a
    "Trail decided" label. Scores are counted, never valued (LAW 1).
  - Gates: per hypothesis × stage, "observed of minimum" chips, with a note that gates count independent platforms.
  - Evidence: admitted by role, rejected by reason, and the number of independent platforms (no quotes).
  - Lived world: clusters with THIN / ANCHOR and their counts against the thresholds.
  - Concepts: each with its reality status and the number of existing products.
  - Unresolved questions.
  - Progress: every manifest step, with loop rounds.
  - Other record keys.
  - Polling every 5 s while live; it stops at a terminal status.
- **Gates from every qualify step** (`run_view.all_qualifications`). A run qualifies per stage (market delta, then supply).
  The compiled result keeps only the newest qualify step's list, so R7's view had shown the supply gates only. The score
  step itself already reads them all. R7 now shows 12 (6 market delta + 6 supply).
- Field and agent text renders as text (React escapes it; a test proves an HTML-looking statement stays text).
