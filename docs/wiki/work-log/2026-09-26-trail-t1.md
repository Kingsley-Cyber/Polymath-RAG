# TRAIL-INTERFACE T1: the Research read model

## Contract
- TRAIL-INTERFACE-V1 §4.2–§4.3 / slice T1 (plan of record 11.504). Owner decisions: watch and read only; friends see only
  their own runs.

## Changes
- **`store.list_runs`.**
  - Newest first. A principal sees only its own runs; no principal (the owner / trusted-local caller) sees every run.
  - Status and adapter filters, a run_id cursor, and a limit capped at 200.
  - The score and refusal counts come from the stored result with `jsonb_array_length`. The score value is never read (LAW 1).
- **`adapter/run_view.py`.**
  - `list_runs`: summaries with a title from the input (`seed`, `seed_idea`, `question`, …) and a one-line outcome ("Waiting
    for your agent", "Stopped: TRAIL_REFUSED", "TrailSignal refused all 6 scores", …).
  - `build_view`: progress over every manifest step (done · current · waiting for the agent / harness · failed · skipped ·
    pending, with loop visits), plus:
    - the output recompiled read-only (`_compile_result(persist=False)`) through the A-15-fixed readers, split into the sections the screens render;
    - the other output keys, contradictions and unknowns;
    - `stored_result_shadowed` when the stored result lost qualifications the steps hold.
- **Routes.** `GET /adapter/runs` and `GET /adapter/{id}/view` (the same run-owner check as every run route). In the web
  boundary's table both are USER class; ownership stays in the route.

  - an unknown principal sees 0 runs.
