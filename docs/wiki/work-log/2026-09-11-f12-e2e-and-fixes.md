## The three defects

**1. The receipt names a chunk three ways, so the evidence join silently matched nothing.**
`final_detail[]` and `legend[]` carry a bare `chunk_id`; `chunks[]` carries only
`locator` = `"chunk:<id>@<start>:<end>"` and **no** `chunk_id`. Joining on `chunk_id` therefore produced ZERO
matches. The visible symptom was damning and completely wrong: the reviewer judged a well-cited answer against
**"0 cited passages"** and returned **0/5 UNSUPPORTED with every claim listed as unsupported** — a confident
verdict manufactured from an empty input. The Evidence Inspector had the same latent bug (chunk rows keyed by
locator never merged with scored rows keyed by chunk_id, so one chunk could render as two). Fixed with one
shared `chunkIdOf()` normalizer; the reviewer then reported "15 cited passage(s)".

**2. A backend route missing from the dev proxy is a silent 404.** Vite answers an unproxied path itself
("did you mean /v2/compare?"), which in the UI is indistinguishable from a backend error. This bit twice —
`/ready` in F1, `/compare` in F12 — so `npm test` now walks the LIVE `/openapi.json` against the proxy list.
**The guard immediately found two more uncovered routes (`/intake`, `/ui_pulse`)** that nobody had hit yet.
It skips when no backend is reachable, so it never blocks an offline build.

**3. The reviewer returned an empty body — the documented DeepSeek-v4 thinking trap.** The default synthesizer
is `litellm:anthropic/deepseek-v4-flash-0731`, which spends its whole budget on hidden reasoning and returns
EMPTY unless thinking is disabled (CONTINUITY §6). Setting it as a top-level litellm param is REJECTED
(`anthropic does not support parameters: ['thinking']`); it must travel as `extra_body`. Also raised to 4000
max_tokens, bounded the prompt to 12×600 chars of evidence, and made an empty completion say WHICH model
returned nothing rather than reporting "unparseable output".

## A fourth, in my own instrumentation

**The cinema backfill's SC2 stop condition fired on a false positive, and the cause was my own D-4 change.**
SC2 read `decreases > 0` on controller rows whose `updated_at` was inside the hour. `decreases` is a LIFETIME
counter, and RPD-DURABILITY-V1 now rewrites the row on EVERY dispatch, so `updated_at` is always fresh — any
lane that had ever backed off tripped it permanently. It halted a run whose terminal states were
**SUCCESS × 170 and nothing else**. Rewritten to measure the DELTA since the run started, corroborated by the
first-class `HTTP_429` terminal state that D-1 provides. A stop condition that cannot distinguish history from
now is worse than none — it trains the operator to ignore it.
