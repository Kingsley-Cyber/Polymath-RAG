# Phase B: production contracts, identity, state, and the no-LLM ingestion layer

## Contract

Admit one change slice that gives the scaffold a working production
foundation:

- the workflow Postgres schema (documents, chunks, entities, evidence,
  facts, artifacts, receipts, outbox, control leases/heartbeats);
- a transactional receipt boundary: stage artifact + receipt + status
  transition + outbox event commit in one transaction;
- full Pydantic contracts for the extraction pipeline (docx §16);
- the deterministic rule pack + compiler (docx §11–§15);
- the no-LLM ingestion layer: sentence-aligned child/parent chunking,
  deterministic extractive summaries, deterministic profile routing;
- host-native deployment: launchd units, Makefile, uv workspace;
- verifiers: determinism, idempotency, and contract tests plus the
  repository guards.

## Changes

- `stores/postgres/migrations/0002_workflow.sql`: workflow authority schema.
  Content-hashed primary keys make replay a no-op by construction.
- `shared/polymath_shared/`: identity extensions (run/receipt/owner/lease
  identity, document byte normalization), typed settings, Postgres pool +
  advisory locks, receipts + outbox, sidecar clients with release-pin
  verification.
- `shared/polymath_shared/rulepack/`: `core-predicates.yaml` (Tier 0 + Tier 1
  vocabulary, 28 predicates), `resource_index.yaml` (curated lexical-resource
  citations), the pure compiler with the §15 compile-time checks, and the
  deterministic negation/modality cue gate.
- `workers/workers/`: `summarizer.py` (no-LLM extractive), `chunker.py`
  (sentence-aligned parent/child), `profile_router.py` (deterministic
  document profiles), `candidates.py` (evidence-anchored pair generation),
  `syntax.py` (spaCy UD adapter, optional), plus the real intake and extract
  workers.
- `orchestrator/orchestrator/`: transactional `/intake` (one run + one
  outbox event per canonical input), run status reads, sidecar registry
  boot-time manifest validation.
- `control/control/`: desired-state census, outbox scheduler, Postgres
  controller lease + heartbeats, the independent tick loop.
- `sidecars/gliner_runtime/`: pinned manifest (urchade/gliner_medium-v2.1 @
  40ec419), weights digest verification (TOFU until Phase C records the
  digest), a `/ready` probe that runs a real forward pass, evidence labels
  generated from the rule pack (single source of truth).
- `deployment/launchd/`, `Makefile`, root `pyproject.toml` (uv workspace),
  `.env.example` typed runtime settings.

## Rejected claims

- No LLM anywhere in the ingestion layer: summaries are extractive, profiles
  are lexical priors, chunk boundaries are sentence-aligned packing.
- The compiler carries no learned edge confidence and no neural override:
  GLiNER proposes, the compiler decides, silence is a valid answer.
- No GPU service in Docker; the GLiNER runtime is host-native.
- Per-package `pyproject.toml` stubs were replaced with real workspace
  metadata instead of a hand-rolled install script.

## Open contract gaps

- Phase C: record the GLiNER weights digest from the qualified Mac and
  replace the `__PIN_WEIGHTS_SHA256__` manifest placeholder; set
  `POLYMATH_REQUIRE_PINNED=1`.
- Projection writers (Qdrant, Neo4j) and retrieval (Phases F–G) are not yet
  admitted.
- `sidecars/embedder` and `sidecars/reranker` remain scaffold stubs.
- spaCy UD orientation is optional; without it the compiler marks
  orientation weak (surface order) — the extraction manifest must record
  which path a run used.
