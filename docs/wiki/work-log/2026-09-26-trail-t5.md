# TRAIL-INTERFACE T5: the dossier on the server, and the owner's Registry

## Contract
- TRAIL-INTERFACE-V1 §4.4, §3.2 (Report, Registry) and slice T5 (plan of record 11.504). Owner decisions: the report is
  rendered on the server from `report.py`; watch and read only; friends see only their own runs; the registry is the owner's.

## Changes
- **`adapter/dossier.py` (new).**
  - `journal_from_store(run, steps, result)`: the governed journal `governed_run.py` writes, rebuilt from the stored rows.
    - One step event per agent-answered step, with the readable evidence `adapter_next` showed. The evidence is hydrated
      from the steps stored before that step; hydration reads stored outputs only, so these are the rows the agent read.
    - One submission event per accepted submission: `reasoning` for AGENT_REASON, `receipt` for HARNESS_ACTION, with
      `adapter_submit`'s status answer.
    - The result event; `built_at` is the result's terminal time (else the run's last update), never now.
  - `render_dossier(journal, layout)`: `governed_run.py report` in a subprocess.
    - This interpreter, a private temporary directory, a minimal environment (no DSN, no token), a 30 s timeout.
    - The engine's module names (`report`, `models`, `graph`) never enter the orchestrator.
    - Typed failures: `DOSSIER_RENDER_FAILED`, `DOSSIER_TIMEOUT`, `DOSSIER_TOO_LARGE`, `DOSSIER_LAYOUT_UNKNOWN`.
  - `sanitize`: re-serializes the page through the renderer's own 21 tags and 4 attributes (`class`, `style`, `title`,
    `colspan`). Text is escaped again. Scripts, links, images, frames, comments and event handlers are dropped.
  - Dossiers exist for `ecommerce.product_research` and `trail.product_discovery`. `report.build_model_from_governed`
    was written for the legacy adapter (docs/27) and reads the newer one's typed product set.
- **`run_view.py`.**
  - `dossier_journal`: a finished run's journal carries the result the view reads (recompiled through the fixed readers,
    with every qualify step's gates), so the dossier and the page show one record. A run stopped by a gap keeps what it
    admitted (tested; a cancelled or failed run takes the same path), so bughunt B-14's symptom does not occur here. A
    live run has no result and reads as in progress. Read-only.
  - The view gains `report.available` and, for the owner only (no principal), `registry`: the snapshot id and content
    hash, the lineage's snapshot ids, and the priors and territories from the run's own Trail outputs.
- **`GET /adapter/{id}/report`** (`layout`, `download=1`).
  - The same owner check as `/view`. A layout outside the renderer's four is a 422 `UNKNOWN_LAYOUT`; an adapter without a
    renderer is a 404 `NO_DOSSIER`.
  - The read and the render run in a worker thread under the request's own principal (`acting_as`). The transaction closes
    before the subprocess starts.
  - Headers: the CSP `default-src 'none'; style-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none';
    frame-ancestors 'self'`, `nosniff`, `no-referrer`, `no-store`; with `download=1`, an attachment named
    `dossier-<run_id>.html`.
  - The web boundary opens it to signed-in users (USER, next to `/view`).
- **The run page.**
  - "Dossier" (a new tab, `noopener noreferrer`) and "Download" links in the header, only when the view says a dossier
    exists. They are plain links: the page never fetches the dossier.
  - A Registry section when the view carries `registry` (the owner): snapshot, priors, territories, labelled
    "Trail registry". Registry text renders as text.
  - `a.btn` shares the button look; a `download` icon (Lucide).

## Proof
- `tests/contracts/test_adapter_dossier.py`, 13 tests. Synthetic rows in TrailSignal's and the store's shapes; no quotes
  from the field.
  - The rebuilt journal EQUALS the one the engine's own `new_journal` / `record_next` / `record_submission` /
    `record_result` build from the tool answers. The reference evidence comes from `service._readable_evidence` over the
    rows stored when each step was issued.
  - A live run: no result, and no submission for its open step.
  - The journal version, the evidence cap and the four layouts are the engine's.
  - Rendered out of process: a `<script>` in a receipt's quote and an `<img onerror>` in an agent statement come back
    escaped. No script, image, frame or link tag, and no event handler, is in the page. The engine's modules never load
    in the test process. The page is deterministic.
  - A run stopped by a gap: its result carries the admission, and its dossier shows the gap and the admitted observation.
  - The sanitizer on hostile markup; a renderer failure is typed.
  - The route: the owner gets 200 with the exact CSP and the other headers; download sets the attachment. A friend gets
    exactly the view's answer for another's run (403). The friend reaches her own run. A live run reads as in progress. A
    Trail-free adapter gets `NO_DOSSIER`; a bad layout gets `UNKNOWN_LAYOUT`.
  - The view: `report.available`, and the registry for the owner only (absent for a principal, `null` for a Trail-free
    run).
  - The boundary classification (GET and HEAD USER, POST unclassified).
- `tests/determinism/test_adapter_dossier_from_store.py`: the complete scripted ecommerce run (stub TrailSignal,
  in-memory store).
  - The host's journal and the rebuilt one have the same 15 agent-answered steps with identical readable evidence, and
    the same 15 accepted submissions with identical status answers.
  - The result output is identical except the rebuilt one adds the 3 market-delta gates to the 3 supply gates.
  - The engine draws the same dossier from both (verdict, scores, refusals, admitted and rejected observations,
    hypotheses, lived world, concepts, leads, packets, registry lines).
- `research.test.tsx` +3 tests: the Dossier and Download links (href, new tab, rel, never fetched); none for an adapter
  without a dossier; the Registry section for the owner's view, as text, and none without it.
- `tests/contracts` 327 passed. The adapter determinism files above, the neutrality pin and the impacted
  evidence-boundary / runtime-pure / MCP tests: 81 passed. Every run used a dead `POLYMATH_PG_DSN`, and a connection
  watcher recorded 0 attempts. vitest 88 passed (the two live-backend files excluded); `tsc` clean. ruff: no new
  findings in changed files.
- Render cost on the synthetic run: about 60 ms per dossier.

## Contract dispositions
- ADAPTER_RUNTIME: TESTED_UNCHANGED. The step, run and result contracts are untouched. The route is a new read-only
  projection, and `dossier_journal` compiles the result with `persist=False`. The contract suite passes.
- MCP_SURFACE: NOT_AFFECTED. No MCP tool changed; the route is web and HTTP only.

## Rejected claims
- "A friend gets 404 for another principal's run": every run route answers 403 `no such run for this principal` to a
  principal, for someone else's run and for a missing one (`_own`). The report route mirrors it exactly; 404 is the
  owner's answer for a missing run.
- "The evidence shown at `adapter_next` is not stored, so the server cannot rebuild it": it is hydrated from stored step
  outputs only. The scripted run shows the rebuilt evidence equal on all 15 steps. What cannot be rebuilt is below.

## Open contract gaps
- **Not in a server journal.**
  - `materials` (computed from the run state at call time): a live run's hypothesis table falls back to the step
    context. A finished run reads the result's semantic view, unaffected.
  - Rejected submissions (the store keeps only a step's last rejection receipt): "Submissions the adapter refused" never
    appears.
  - Status polls: the audit line's event count differs from a host journal.
- **Registry coordinates are not a secret boundary.** A friend's own `ecommerce.product_research` run already carries its
  priors, territories and snapshot id in `/adapter/{id}/result` (USER class) and in the dossier's own "Registry
  Coordinates" line. The owner-only block is where the owner reads them. Withholding them from friends everywhere is an
  owner decision.
- **The engine, not this slice.**
  - `report.py` interpolates a few values without escaping (score, confidence, subscore values, VOI, cluster and job
    counts). The sanitizer and the CSP neutralize any markup there, but the engine should escape them.
  - Server dossiers show bughunt B-12 (an empty qualification state: the renderer reads `verdict`/`status`, Trail sends
    `state`), and B-13 / B-16 / B-39 / B-40 as listed.
- **Where support is declared.** Which adapters have a dossier is a list in the read-side `dossier.py`. The manifest
  schema is closed, so making it manifest data is a manifest-contract change.
- **Not in the contract map.** The journal format coupling (`governed_run.py` / `report.py` ↔ `journal_from_store`) is
  pinned by tests, not declared in `architecture/contract-dependencies.yaml`.
- **Not run.** No live dossier of R7 (live reads were out of scope for this slice) and no screenshots (the dev server
  proxies to the live backend).
- **Deploy.** The orchestrator needs a bounce after merge; the frontend needs `npm run build`.
