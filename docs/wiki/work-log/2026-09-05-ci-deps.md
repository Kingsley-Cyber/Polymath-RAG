# WORK LOG — CI-DEPS-V1

Owner (2026-09-05): "fix the determinism and contracts CI too."

## Contract

- `determinism` and `contracts` install what the suites import: `pip install pytest jsonschema "mcp>=2,<3" -e ./shared -e ./workers -e ./orchestrator -e ./control`.
- `determinism` provides the dev Postgres the tests hard-code (`postgresql://polymath:polymath-dev@127.0.0.1:5432/polymath`): a `postgres:16-alpine` service with those credentials and every file in `stores/postgres/migrations/*.sql` applied in order with `ON_ERROR_STOP` — the same schema `make db-migrate` produces (verified locally on a fresh container: 51 migrations, 64 tables).
- Tests that read data the dev machine happens to hold (rebuild corpus documents, the mention ledger) skip on an empty store; they never fail CI for the absence of local history.

## Why

Both workflows had been red since they were wired: they installed only `pytest` (and `jsonschema`), so every module failed at collection — 64 errors in determinism (`psycopg`, `pydantic`, `httpx`, `yaml`, `fastapi`, `numpy`, `mcp`), 2 in contracts (`pydantic`). A red-since-birth check is no check; the SUMMARY-SWEEP-SERIALIZATION-V1 regression (a real-Postgres test) could only run locally.

## Changes

- `.github/workflows/determinism.yml`: dependency install, Postgres service + migrations step, `pytest tests/determinism/ -q`.
- `.github/workflows/contracts.yml`: dependency install.
- `tests/determinism/test_llm_controller.py`: the batched-call fake accepts `use_lean` / `system_prompt` (the impl gained them; the test had gone stale).
- `tests/determinism/test_source_recovery_key.py`: `pytest.skip` when the rebuild corpus has no documents on this store.
- `tests/determinism/test_killchain_pass2.py`: `pytest.skip` when the mention ledger is empty.
- `stores/postgres/migrations/0052_schema_drift_ci_deps.sql`: the first CI run on the migrated schema failed 10 stall-tracer tests with `column t.last_error_note does not exist`. Diff of the migration-built schema against the dev database: `stage_tickets.last_error_note` (written in five places, NO migration anywhere — a fresh install broke on its first failed ticket), plus `runtime_signals` and `llm_providers` (created lazily in code). The migration adds all three idempotently; after it the fresh schema equals dev column for column (0 drift), and it is a no-op on dev.
- TREE rows (`scripts/scaffold_polymath_v4.py`), register 11.76.

## Proof

- CI-equivalent local run (fresh venv, same pip line, dev Postgres): before the test fixes 7 failures, all explained (5 × missing `mcp`, 1 stale fake signature, 1 data-dependent assertion); after: the four touched files → 22 passed, 1 skipped; full suites earlier in the same venv → everything else green.
- Migrations on a fresh `postgres:16-alpine`: all 52 applied; `information_schema.columns` of the fresh database equals the dev database (630 → 640 columns after 0052; drift 0).
- GitHub Actions on the commit that lands this (recorded in the register row once green).

## Rejected claims

- "Skip the DB tests in CI" — rejected: 20 files exercise the real ticket/receipt tables; a service database is cheap and keeps them real.
- "Pin a lockfile first" — deferred: the workspace has no `uv.lock`; the members' version ranges resolve today, and a lock is a separate hygiene change.

## Open contract gaps

- Tests that depend on locally-ingested corpora (`cysa-study-v1`, the mention ledger) still measure nothing in CI; a seeded fixture corpus would make them real there.
- `research-harness` only runs on `research/**` paths; the other three run on every push.
