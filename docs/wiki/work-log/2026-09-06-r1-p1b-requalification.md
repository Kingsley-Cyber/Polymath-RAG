# WORK LOG — R1 P1.b requalification

Plan gate (ledger row, read from disk before this phase): *multi-dimension fixture: every dimension ✓ or explicitly flagged weak; no document exceeds one vote per subquery; wall p50 ≤ baseline + 3 s.*

R0 (commit a0b0525) reconciled the record first: P1.b was labelled DONE in the continuity report and register row 11.92 while two of its gates were MISSED (strict 0.883 / system-honest 0.983 against 1.0; wall +4.65 s against +3 s; four measured attempts). The label is now IMPLEMENTED — QUALIFICATION OPEN; the measurements were not touched. This log records the requalification and the disposition.

## Contract

- **What "flagged weak" means for the PRIMARY.** After correction D a compare request compiles to PRIMARY (side A) + COMPARISON (side B): the primary *names a dimension*. The P1.b code excluded q0 from the `below_floor` rule, so a side-A dimension whose every judged candidate the cross-encoder rejected was shown as covered while side B, in the same state, was flagged. The contract ("every dimension ✓ or explicitly flagged weak") admits no such asymmetry; the system must never present a requested dimension as covered when its evidence is judged irrelevant. The floor is the one already frozen for subqueries (`aspect_weak_floor` 0.5 on the judge sigmoid, i.e. logit < 0); `no_candidates` already applied to the primary. With a degraded judge (no scores) nobody is flagged on the floor — unchanged.
- **Two readings of the dimension gate, reported separately (goal R1.1).** *System-honest*: the answer shows evidence the judge accepted (sigmoid ≥ 0.5) for a query naming the aspect, or the aspect is explicitly flagged — this is the gate as written. *Strict*: the aspect's gold chunk or a chunk of its own document is seated for a query naming it — the executor's stricter reading from P1.b, which has a retrieval ceiling (below).
- **Measurement contract (new).** `eval/fixtures/chat_multi_M_plans.json` freezes the compiled plan of each M question (latest receipt with a plan, 2026-09-05 22:58–23:07 UTC; 20 plans with 2 queries, 9 with 3, 1 with 4). `scripts/chat_m_replay.py` replays them through `chat_retrieve_v2` (the chat path's engine call) in two arms interleaved per question — `single` (PRIMARY only = `v2-single`) and `multi` (PRIMARY + typed subqueries = `v2`) — scores both with `chat_baseline.aspect_stats`, computes the pre-R1 ("legacy": primary never flagged) reading from the same run, and receipts per-stage latency plus the MPS OOM events each sidecar logged inside the turn's window. A "clean turn" is a turn with zero OOM events in both sidecars.

## Open contract gaps

1. **Absolute latency under systemic GPU contention (P1.d).** Both MLX sidecars share one Metal device with the enrichment embedder; a chat turn's 1–2-text embedding waits 3–4 s behind 8-item enrichment batches and a 20-pair rerank stretches from 4.5 s to 27–52 s whenever a batch coincides (OOM events during the replay: embedder 7, reranker 10; 20 / 23 of 30 turns per arm were clean). The relative gate is met; the absolute budget (§3.16: core lanes 3.0 s + rerank 3.0 s) is not reachable on this machine until interactive work has priority over enrichment on the device — the resource-control fix the goal assigns to P1.d (interactive lease / priority in the shared Metal discipline, per-stage deadlines with degraded receipts). Recycling the sidecars removes fragmentation, not the contention.
2. **Strict ceiling.** Five strict misses remain in the P1.b arm, all system-honest ✓ (judge-accepted evidence shown for a query naming the aspect): "Nonsquare Pixels", "Miscellaneous Drawing Tips" and "Movement of an Object with a Background" have their gold in the union but outranked by another document's judged-relevant chunk (a selection / composition matter — P1.c measures whether the composer or a wider judged prefix seats them); "OEBPS/ritc 9781119685401 epub3 035 r1.xhtml" (an EPUB file-name heading) and "Multiple moments" never enter the union (heading-only anchors that neither dense nor sparse ranking reaches inside the merged cap — a candidate-pool ceiling, §3.8 step 2, not a coverage defect). Strict is therefore reported with its ceiling; it is not the gate as written.
3. **Single-query plans carry a weak primary in receipts only.** `_coverage_lines` is emitted when the plan has ≥ 2 queries (P1.b decision); a single-query turn whose every candidate is below the floor is flagged in `weak_aspects` but the model is not told. Whether to name it in the prompt is a synthesis-contract question (P0.d's abstention already handles the no-support case) — for P1.g's absent-term case.
4. **Compiler lane skew in the frozen plans.** 27 / 30 recorded plans came from `compiler_alt` (mistral-small) and 3 from `compiler1` (gemini flash-lite); the frozen file is a replay fixture, not a statement about the lane mix.
