### OpenCode in this environment (what made the model calls reliable)
1. `opencode run -f` takes a LIST: the message must come before `-f`, or it is swallowed as a file name.
2. The agent treats an attached file as data (it refused instructions placed in the attachment), so instructions go in the message.
3. A second, long-running `opencode serve` on the Mac holds OpenCode's shared SQLite store and lock directory: the wiki's calls run
   with their own `XDG_DATA_HOME` and `XDG_STATE_HOME` (the login file is linked, never read or copied).
4. **The decisive one:** OpenCode takes its project from `$PWD`, which a subprocess `cwd=` does not change. Launched from the
   repository, every call treated the whole repo as its project and failed in 0.8 s ("UnknownError") or hung after `init`; hand
   calls launched from the run directory worked. `PWD` + `--dir` fixed it: 0 failed calls in the full run.
5. The `title` agent (an extra model call per session) is disabled; starts are spaced 10 s, 3 workers (Hermes shares the plan).
