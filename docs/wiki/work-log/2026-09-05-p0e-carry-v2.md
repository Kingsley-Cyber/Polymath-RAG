# WORK LOG — P0.e carry v2

Plan gate (ledger row, read from disk): *off-topic turn-1 chunk absent from turn-3 legend; prompt tokens per turn ≤ baseline.*

## Contract

- **Client law (App.tsx).** Carry = for each earlier assistant message, newest first: legend entries whose `chunk_id` ∈ that answer's `used_evidence`, deduped by locator, cap 8, each `{locator, preview, chunk_id}`. The retrieved inventory (`retrieval.chunks`) is never carried.
- **Backend law (`_carry_candidates` → `_admit_carry`).** Normalise (explicit `chunk_id`, else parsed from `chunk:<id>@a:b`; anything else is `dropped_unparsed` — document/section summaries are routing, not evidence), dedupe, drop ids in this turn's `evidence_rows` (`dropped_already_retrieved`), hydrate via the assembler's `_resolve_chunk` (`dropped_missing` for gone or hidden chunks), score every survivor against the resolved request with the reranker sidecar in one batched call, drop `< floor` (`dropped_floor`, scores recorded), keep the top `cap` by score (`dropped_cap`). Admitted items become bundle items `{lane: carry, kind: carried, carried: true, carry_score}` in the assembler's shape; `_evidence_legend` tags them after this turn's evidence and marks `carried`. Turns that skip retrieval (conversation policy) skip carry admission too (`skipped: no_retrieval_turn`).
- **Floor scale.** The sidecar returns raw cross-encoder scores, not probabilities (§ Proof: on-topic carried chunks +1.1 … +6.9, off-topic −3.25 … −11.9). 0.25 sits in that gap with margin above 0; it is an env knob and every dropped score is in the receipt, so a re-calibration is a measured change, not a guess.
- **Degradation.** Reranker unreachable ⇒ no floor, newest-first + cap, `degraded: carry_rerank_unavailable:<Exc>` in the accounting (counted, surfaced, never silent).
- **Accounting.** `retrieval.carry` = `{in, dropped_duplicate, dropped_already_retrieved, dropped_unparsed, candidates, hydrated, dropped_missing, dropped_floor, scores_dropped_floor, dropped_cap, admitted, floor, cap, degraded, scores, admitted_ids}`; `result.meta.prompt` = `{prompt_chars, messages, carry_in, carry_in_prompt}`; both in the receipt.
- **Frozen and untouched:** chat-intent-plan-v1, SYNTHESIS-V2, funnel, lane budgets, reranker batching, CORPUS-STYLE-V1.

## Proof

Probe: `scripts/chat_carry_probe.py` — 3 fixed turns on `cinema` (T1 "What does the book say about nonsquare pixels?" = off-topic; T2 "…making your own chroma keyer?"; T3 "How does that work in practice?"), compiler on, the UI's default LLM synthesizer, carry built client-side per policy, `result.meta.prompt` / `retrieval.carry` from the answer events. |---|---|---|---|---|
| off-topic turn-1 chunks in turn 3's prompt (legend ∪ admitted carry) | 0 | **5** (of 30 carried; the prompt block had no legend, so they were cited by raw locator when used) | **0** | **0** |

**Score separation that sets the floor** (raw sidecar cross-encoder scores, resolved request "how does making your own chroma keyer work in practice" / "…chroma keyer"): on-topic carried chunks admitted in an earlier v2 run scored **+6.88, +2.50, +1.13** (and +6.06 / +5.13 / +3.38 / +2.88 for v1 inputs); every off-topic carried chunk scored **−3.25 … −11.94** (T2: −8.6 … −11.9; T3: −8.1 … −11.3; v1 inputs T3: −3.25 … −9.0). `POLYMATH_CARRY_ADMISSION_FLOOR = 0.25` sits inside a gap of > 4 points on either side. Reranker degradation: none in any run (`degraded: null`).

**Why admitted was 0 on the final v2 run.** The compiled follow-up ("how does making your own chroma keyer work in practice") re-retrieved every chroma-keyer chunk itself, so the carried on-topic chunks were `dropped_already_retrieved` (4 / 4) rather than admitted — the correct outcome (no duplicate evidence in the prompt). The earlier v2 run, where turn 3's retrieval missed three of them, admitted exactly those three with positive scores. Carry now adds only what retrieval did not already bring.

Tests on the shipped code: `test_chat_carry.py` 3 unit + 1 live (v2 probe with the deterministic synthesizer: no leak, admitted ≤ 8, floor/already-retrieved accounting closes) with the rest of the chat suite (`test_chat_synthesis`, `test_chat_hygiene`, `test_chat_funnel`, `test_chat_compiler`) — 36 live/chat tests green; offline determinism suite 1316 passed / 11 skipped; frontend `tsc --noEmit && vite build` clean; `scripts/repo_guard.py` clean.

## Rejected claims

- "Carry only needs a smaller cap." Rejected by measurement: with the v1 policy 5 turn-1 chunks still reach turn 3 under a newest-first cap of 30, and a cap alone keeps the inventory as the source. Source (used only) + backend admission (rerank + floor) is what removes them; the cap is the last guard.
- "The frontend rule is enough; the backend can trust the client." Rejected: the backend receives whatever any client sends (old bundles, MCP, scripts). Measured: 30 v1 locators through the v2 backend → 0 admitted with every off-topic score ≤ −3.25; the law lives server-side.
- "Carry previews are enough to rerank." Rejected: previews are 220 chars; admitted evidence is re-hydrated to the full chunk and truncated by the same `_EVIDENCE_TEXT_CHARS` as fresh evidence, so a carried [S#] is as citable as a retrieved one.
- "Carried items should stay outside the legend." Rejected: outside the legend they were cited by raw locator (the CITATION-TAGS-V1 leak) and invisible to `used_evidence`, which is exactly what made carry unbounded across turns.

## Open contract gaps

- On this probe the compiled follow-up re-retrieved every on-topic chunk itself, so carry admitted 0–3 items; carry earns its keep on turns whose compiled query drifts from the antecedent (P1 fixtures will measure that). The accounting is in every receipt to watch it.
- `_CARRY_ADMISSION_FLOOR` is set from one corpus's separation; the sidecar's score scale is model-specific. A reranker model swap must re-measure (`scripts/chat_carry_probe.py --policy v2`).
- Earlier-artifact summaries beyond the compiler's one-line antecedent (§9.3 second half) remain a P1.f item; carry v2 covers evidence, not artifacts.
- The frontend does not yet render the `carried` badge in the Sources panel; data is in the answer event.
