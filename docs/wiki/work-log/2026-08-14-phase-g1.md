# Phase G1: document semantic routing + retrieval primitives

## Contract

Admit the retrieval primitives without making ingestion responsible for
retrieval behavior:

- a document-level semantic routing profile, built bottom-up and
  deterministically (no LLM), distinct from the ingestion profile;
- three parallel lanes — document router, parent router, global child —
  fused deterministically, with document routing never a recall gate;
- bounded graph expansion as an addition, never the recall gate;
- the cross-domain validation query as the acceptance test.

## Changes

- `workers/document_profile_builder.py`: RetrievalProfile built from
  parent summaries, top entities, predicate distribution, and the
  ingestion profile — deterministic aggregation, contract
  `document-summary-v1`, with source_parent_count /
  summarized_parent_count / coverage fields (incomplete profiles are
  visible, never silently accepted).
- `workers/profile_worker.py`: the `profile_document` durable stage;
  the census chain grows to six stages
  (intake → extract → profile_document → project_qdrant →
  project_neo4j → verify_projections).
- `shared/retrieval.py`: deterministic lexical scorer (stopword-filtered,
  BM25-flavored), weighted profile-field scoring with "why" traces,
  reciprocal-rank fusion across the three lanes, sibling expansion under
  parents, and bounded graph expansion (2 hops, high/medium-weight
  predicates only).
- `orchestrator/api/retrieve.py`: POST /retrieve returns the routing
  TRACE — document ranking with reasons, parent hits, child evidence,
  graph facts. Child hits survive zero-scoring documents by design
  (tested).
- `shared/stores.py`: projection store driver factories — the
  orchestrator reads stores without importing workers (forbidden edge
  eliminated).
- Migration 0003: documents.retrieval_profile + coverage columns.
- Deployment: launchd unit + Makefile target for the profile worker.

## Proof

- Cross-domain acceptance: the validation query routes to
  Loop Engineering (rank 0), Predicate Compiler (rank 1), Prompt Graph
  (rank 2) — three conceptually complementary sources discovered from
  one query that no single document answers; unrelated filler stays out
  of the top ranks (integration test, live stores).
- Recall-gate invariant tested: a child hit survives when its document
  scores zero.
- Full suite: 26 unit + 9 integration tests + 3 guards green.
- Live /retrieve trace produced over real stores.

## Rejected claims

- No LLM in the profile builder or the scorer (the neural embedder and
  reranker remain Phase G contract additions).
- No answer generation in this phase: /retrieve returns evidence +
  provenance; answer assembly is G5.

## Open contract gaps

- G2 fusion with the neural embedder contract; G3 reranking; G4 graph
  expansion policy tests; G5 answer/evidence assembly.
- The retrieval profile's semantic_summary is extractive; richer text
  behind the same contract shape is a future summarizer swap.
