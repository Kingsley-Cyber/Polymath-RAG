## Changes

**GRAPH-BROWSE-V1** (`GET /graph/entities`, `GET /graph/entity/{id}/relationships`) — closes GAP-7.
Read-only, corpus-scoped, bounded (≤100). **Source-attested by construction:** Neo4j holds the topology but
carries no corpus and no provenance, so a relationship is served ONLY when Postgres
`evidence(fact_id, doc_id, chunk_id)` ties it to a document in the requested corpus. Unattested relationships
are withheld and **counted** (`dropped_unattested`) so their absence is visible.

**COMPARE-RETRIEVAL-V1** (`POST /compare`) — closes GAP-2. One question, several modes, **retrieval only**,
arms **sequential** (the reranker is one shared GPU lane; parallel arms were measured at p50 12s→31s, so
parallel latencies would be meaningless). Arms differ ONLY by mode — no knobs are forwarded, or the comparison
stops being about the mode. VECTOR is refused with 422.

**ANSWER-REVIEW-V1** (`POST /review`) — closes GAP-3. Evaluation only: question + answer + citations +
the evidence that answer cited → structured verdict (grounding · correctness · completeness · citation
support · retrieval adequacy · unsupported claims · missing evidence). It performs **no retrieval** and
judges the answer handed to it — the distinction from `synthesizer`, which merely re-answers.

Frontend: `screens/Compare.tsx` (F6, user-triggered, with document-overlap analysis),
`components/AnswerReview.tsx` (F7, per turn), `screens/Graph.tsx` rewritten on the real API (F9).

## Proof

- **Live `/compare` on `rag-canary`:** HYBRID 412 ms · GRAPH 508 ms · WILDCARD 819 ms, each
  `evidence=15 docs=6 union=51 rows=15`. All three arms selected the SAME documents — on a small homogeneous
  corpus the modes genuinely converge, which the UI states as a result rather than hiding.
- **Live `/graph/entities?corpus_id=cinema&q=laban`:** `laban movement analysis` (32 mentions, 10 documents),
  `labanotation` (17/7) …; relationships returned `laban movement analysis -USES-> bayesian models` with its
  attesting document and the passage text, `dropped_unattested: 0`.
- **F11: 9/9 integration tests pass against the live backend**, including the legacy-boolean case (cinema
  `query_ready: true` while VNEXT is INCOMPLETE — it skips itself once cinema completes, so it cannot rot into
  a false assertion), the FIRED-vs-SURVIVED trace fields, source attestation, and the two refusals.
- `npm run build` (tsc strict) green.

## Rejected claims

- **"Let `/compare` forward `latent` and other knobs."** REJECTED — caught at first run (`chat_retrieve_v2`
  does not take it) and then rejected on principle: an arm that differs by more than the mode is not a
  comparison of modes.
- **"Reuse `_run_synthesizer` for the reviewer."** REJECTED — that symbol does not exist; I had guessed it.
  The reviewer now goes through the same `litellm.completion` + `_litellm_credentials` path the chat
  synthesizer uses, so a model that works there works here, with `max_tokens=2000` (reasoning models return
  EMPTY at a tight bound — CONTINUITY §6).
- **"Derive `entity_id` by hashing the surface."** REJECTED — re-deriving an id convention is exactly what
  silently broke the vector↔graph join before. Ids are read FROM the graph.
- **"Serve unattested relationships greyed out."** REJECTED — the plan says only source-attested
  relationships may appear as canonical truth. They are withheld and counted.

## Open contract gaps

- `/compare` does not synthesise, so it compares RETRIEVAL, not answers. Comparing answers would cost N
  syntheses; that is a deliberate omission, not an oversight.
- The reviewer's own reliability is unmeasured — it is a second model, not an oracle.
- Graph entity search ranks by mention count; there is no semantic entity search.
- F12 (real browser E2E) still to run.
