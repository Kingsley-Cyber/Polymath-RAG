# WORK LOG — MEDIC-V1

Owner (2026-09-05): "I need this auto-healing and correcting itself when I leave or go to sleep. I shouldn't have to talk to Claude to have it running again."

## Contract

- **Law 1 — capacity re-arm.** Each tick, a ticket in `failed` whose latest `stage_attempts.error` (or `last_error_note`) carries `HTTP 429`, `429 Too Many Requests`, `lane refused` or `LIMITER_REFUSED` is set back to `ready`, `attempt 0`, lease cleared, note `MEDIC re-armed …`. At most `medic_rearm_per_tick` (20) per tick and `medic_per_ticket_daily_cap` (5) per ticket per 24 h; past the cap the refusal is receipted and the ticket stays failed. A ticket with any other error is never touched. Pinned by ticket id, never a status sweep.
- **Law 2 — deadlock break.** A session in `wait_event_type = 'Lock'` for ≥ `medic_deadlock_wait_s` (120) whose `pg_blocking_pids` blocker is `idle in transaction` for ≥ the same threshold: the blocker is `pg_terminate_backend`-ed (its transaction rolls back, the waiter proceeds). Postgres cannot see these cycles when one edge is a Python-side wait (the summary_jobs deadlock of 02:23Z had exactly this shape). Both pids and both queries are receipted.
- **Law 3 — receipts.** Every action is a row in `medic_actions (kind, target, detail, at)`; `/health/pipeline` exposes the last 15 min.
- **Law 4 — DEGRADED is a state.** `pipeline_health` returns `DEGRADED` (causes = open `stall_traces` diagnoses × counts) when episodes are open and traced within 10 min, or the medic acted within 15 min; HEALTHY only when tickets flow and nothing is traced as stalled. BLOCKED / IDLE branches are unchanged and still take precedence.
- **Law 5 — orchestrator limbo.** The `orchestrator` slot carries its own readiness policy (`readiness_interval_s 20`, `readiness_failures_before_restart 3`), so a uvicorn that is alive but not listening is replaced within ~60–90 s instead of ~10 min.
- The medic runs in its own savepoint; a failure inside it logs `medic failed` and never aborts the tick.

## Why (measured)

- 02:23Z: cross-process deadlock on `summary_jobs` looked like healthy idleness for 20+ minutes until a human read `pg_stat_activity`. Serialization (11.75) removes the known cause; the breaker removes the class.
- 04:32–06:34Z: seven extraction tickets went `failed` on three consecutive 429s; 11.78 stopped the budget burn for future events, but tickets already failed needed a human `UPDATE`.
- 09:2x: `kill -TERM` on the orchestrator left uvicorn alive with the port closed; the supervisor's 5 × 120 s policy would have kept the API down for 10 minutes. `kill -9` fixed it — by hand.
- `/health/pipeline` said HEALTHY while 41 `parent_enrichment` tickets were traced READY_UNCLAIMED.

## Proof

- `tests/determinism/test_medic.py`: 5 passed against the dev Postgres (0053 applied). The deadlock test holds a row lock idle-in-transaction on session A, blocks session B on it, and asserts the medic from session C terminates A, B commits (`v = 10`), and exactly one `DEADLOCK_BREAK` receipt names A's pid.
- Live: `control.main` restarted 09:47Z on the new tick; `medic_actions` holds 0 production rows (nothing to repair at restart: the 3 failed tickets are `intake` with non-capacity errors, no lock waits). The corpus-wide `project_qdrant` pass (lease 2 h, its outer transaction idle between batches) was NOT touched — no waiter, so Law 2 does not fire; this is the intended asymmetry.
- Supervisor fence auto-heal (WORKER-QUARANTINE-AUTOHEAL-V1) observed working three times during this change (09:23, 09:41, 09:43): every edit to fleet-loaded files quarantines the fleet, and the supervisor restarted all slots within ~2 min each time. Cost of editing live: one restart round per burst.

## Rejected claims

- "The medic should restart wedged workers." Rejected: the supervisor already owns process life (readiness probes, fence quarantine, restart budget); the medic owns database state. One authority per failure class.
- "Break any long idle-in-transaction session." Rejected: the project_qdrant outer transaction is idle between embed batches for hours by design; without a waiter it harms nobody. Only a waiter + idle blocker pair is a deadlock.
- "Re-arm by status sweep." Rejected by the medic scoping law: re-arm pins ticket ids whose latest error is a capacity marker.

## Open contract gaps

- The supervisor process itself still runs the pre-change code: per-slot readiness (Law 5) takes effect at the next supervisor restart, deferred until the cinema ingest completes so the 2 h projection pass is not killed. `control.main` already runs the medic.
- `tests/determinism/test_stall_tracer.py::test_ready_without_claim_event_and_without_live_slot` and five sibling stall-tracer tests fail identically on unchanged `main` against the dev store (probe tickets are not traced at all; 42 open episodes, so not the `_LIMIT` cap). Cause not yet traced; not introduced here (the medic does not touch the tracer). Tracked as a follow-up.
- Re-arm decisions read `stage_attempts.error`; a stage that fails without writing an attempt row is only re-armed if `last_error_note` carries the marker.
