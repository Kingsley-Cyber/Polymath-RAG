# CI-GREEN-V1: GitHub CI green again

## Contract
- The owner, 2026-10-01: "fix the CI too". At `43ca3092` GitHub CI was red: `contracts` 1 failure, `determinism` 12.

## Changes
- **A real crash (8 of the 13).** `evidence_boundary.knowledge_passes` and `_receipt_view` iterated / measured a step output's
  `rows` and `graph_rows` without checking they are lists. A step output is JSON a harness may submit; `{"rows": 2}` (a count)
  raised `TypeError: 'int' object is not iterable` in `_context_refs`, i.e. in every later step of that run. The harness and
  product-discovery tests' fake executors return exactly that, so 7 tests failed, and the crashed runs stayed `running` in
  CI's shared database, where the lease test then claimed one of them instead of its own run (the 8th). Fix: `_row_list()` —
  a non-list value counts as no rows (the output still marks a knowledge pass). Regression test
  `test_a_step_output_whose_rows_is_not_a_list_never_crashes_the_run`.
- **Missing dependencies (2).** `litellm` is imported by the orchestrator (chat synthesis, review, deep research) but was never
  declared, so a fresh install lacked it: `orchestrator/pyproject.toml` now requires `litellm==1.98.0` (the fleet's version;
  the live venv already has it). The offline GNN trainer test needs `torch`: the determinism job installs the CPU wheel
  `torch==2.13.0` (the fleet's version) from the PyTorch CPU index first. Resolution checked for Linux / Python 3.11 with
  `uv pip compile`: no conflicts, no CUDA packages.
- **Tests that fell behind the code (3)**, each updated to the behaviour of a feature with its own tests:
  - `test_chat_runtime`: the engine call now carries `keep_latent`, `latent_bridge_ids` and each subquery's origin and
    `derived_from` (WLK2C 2026-09-19, the bridge pass 2026-09-22); the test's point — both routes make the SAME call — holds.
  - `test_document_profile_stage`: the profile step also writes the atom lane into its own collection since
    PROFILE-ATOM-DAG-WIRING-V1 (2026-09-17); the test still demands exactly one profile write, plus exactly one atom write.
  - `test_query_receipts`: `chat.py` holds two receipted routes since REASONING-BOUNDARY-V1 (`/chat`, `/chat/evidence`); the check
    now reads each route (AST) and demands a success AND an error receipt on every one, instead of a file-wide count of 2.
