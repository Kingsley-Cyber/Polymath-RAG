# Glossary

Domain terms of this codebase, each anchored to where the code uses it most (generated by `scripts/codewiki/pages.py glossary` from the code, not from status documents).

**parent** — a heading-bounded chunk of one document (the author's own sections) with byte-exact source offsets, produced by the tier chunker under contract `chunk-structure-v3`; the unit the parent-map stage maps and lane A (dense-parent) retrieves.
`workers/workers/tier_chunker.py:4` [DERIVED]

**child** — an exact-substring chunk inside a parent, produced by the same tier chunker; the evidence-proving unit of retrieval ("SUMMARIES ROUTE / CHILDREN PROVE / GLOBAL CHILD SEARCH PROTECTS RECALL"), reached by descending document → section → child.
`workers/workers/tier_chunker.py:11` [DERIVED]

**chunk** — the split unit of a document (parents plus children) that the `project_qdrant` stage projects per-corpus into the Qdrant collection together with routing representations.
`workers/workers/project_qdrant_worker.py:3` [DERIVED]

**pMAP** — parent-map coverage arithmetic over the migration-0054 tables, joined into the canonical per-document status aggregate (exact counts + ordered blocker list).
`shared/polymath_shared/document_status.py:5` [DERIVED]

**parent map** — the per-document mapping of every retrieval-eligible parent produced by the auto-minted `doc_parent_map` stage (readiness floor `unresolved_eligible_parents == 0`); read by the candidate engine, chat retrieval, and its own projection module.
`shared/polymath_shared/document_profile/parent_map_projection.py:1` [DERIVED]

**facet** — a typed coverage dimension of the chat plan and facet retrieval (FACET-RETRIEVAL-V1); heaviest users are the query-plan compiler (`chat_plan.py`), the facet definitions (`facets.py`), wildcard mapping and the UI.
`shared/polymath_shared/chat_plan.py:100` [DERIVED]

**subquery** — one of the typed search queries a chat plan emits (the plan carries 1–4 of them); the candidate engine runs them as lanes and `subquery_provenance.py` tracks their provenance.
`shared/polymath_shared/chat_plan.py:79` [DERIVED]

**lane** — an independent retrieval path the candidate engine runs and unions with full provenance: A `HIERARCHICAL_ROUTE`, B `GLOBAL_DENSE_CHILD`, C `GLOBAL_SPARSE_CHILD`, additive lanes D–G, graph/GNN arrivals; separately, an LLM lane is an account × model × stage assignment in the accounts registry.
`shared/polymath_shared/candidate_engine.py:5` [DERIVED]

**seat** — a held slot for an evidence candidate in the bounded synthesis set ("librarian evidence seating" in `latent_portfolio`/`latent_selection`); the candidate engine composes seats and the UI displays them.
`shared/polymath_shared/latent_portfolio.py:9` [INFERRED: seating named in the latent_selection bundle purpose; seat policy lives in latent_portfolio/evidence_utility]

**atom** — a routing surface lifted from a compiled profile into a `document_profile_atoms` row ("one atom = one dense vector"): THEORY / CONCEPT / LATENT-PATTERN / BOUNDARY / SEEALSO / BRIDGE / ANCHOR / TENSION / INVERSION / RECALLQ; used for semantic routing/expansion, never factual evidence.
`shared/polymath_shared/document_profile/profile_atom.py:1` [DERIVED]

**profile atom** — the full name of an atom once projected: one dense point per atom (named vector `"atom"`) in a per-embedding-contract Qdrant collection, a rebuildable cache of ACTIVE Postgres rows gated by `reconcile()`.
`shared/polymath_shared/document_profile/profile_atom_projection.py:1` [DERIVED]

**document profile** — the `doc_profile` stage artifact: lean context → enrichment LLM (isolated `doc_profile` pool) → deterministic compiler (rag-profile-v3) → profile artifact → vector projection in its own Qdrant collection, all in ONE stage transaction with receipt chain content hash → input hash → raw response hash → compiled hash → projection hash.
`workers/workers/doc_profile_worker.py:1` [DERIVED]

**vNext** — the newer of the two per-document readiness verdict tracks (legacy + vNext) joined into canonical document status; its completion state is `VNEXT_COMPLETE`.
`shared/polymath_shared/document_status.py:6` [DERIVED]

**section profile** — the per-section counterpart of the document profile; profile atoms are lifted from compiled document/section profiles.
`shared/polymath_shared/document_profile/profile_atom.py:25` [INFERRED: single-mention term; profile_atom lifts atoms from document/section profiles]

**giant document** — a document with >300 parents, profiled by `giant_profile.py` via a section plan (`section_groups`), one LLM fingerprint per section (`build_section_fingerprint`), and a stratified profile — fixing the failure where `handbook.html` (802 parents) got a 5-sample profile naming nothing past the front matter.
`shared/polymath_shared/document_profile/giant_profile.py:67` [DERIVED]

**receipt** — durable proof of a committed operation: the doc_profile stage commits a hash receipt chain, adapter runs record step receipts, and the UI/chat path handle them per turn; heaviest user is the adapter-run service.
`shared/polymath_shared/adapter/service.py:279` [INFERRED: adapter service is the top user; receipt chain quoted in the doc_profile stage purpose]

**query receipt** — QUERY-RECEIPTS-V1: one durable row per served query in `query_receipts` (migration 0047); every `/chat`, `/ask` and `/retrieve` writes ONE row after the response is composed — best effort, own short transaction, never on the critical path, failures logged and swallowed.
`shared/polymath_shared/query_receipts.py:214` [DERIVED]

**chat plan** — CHAT-INTENT-PLAN-V1: the machine-readable plan the conversation-aware compiler builds from (message, recent history) — resolved_request, task type, retrieval need, 1–4 typed search queries with exact terms preserved verbatim; read back by receipts, wildcard mapping and lineage.
